# 周公解梦：前端与接口逆向分析

## 结论与证据边界

目标是 Next.js / React 页面。客户端负责收集梦境及补充线索、鉴权入口、积分预检、请求编排、文本流接收和 Markdown 展示。已捕获的解梦路径中没有本地梦境词典匹配引擎；实际解梦由 `/api/dream` 的服务端完成，服务端内部实现未知。

“页面逻辑已恢复”和“解梦算法已恢复”是不同结果：本次交付前者以及客户端接口协议。

## 输入契约

源位置：`readable/dream-page.readable.js`，Webpack 模块 `49442`，页面组件 `W`。

| 字段 | 前端类型、值 | 含义 |
| --- | --- | --- |
| dreamContent | string，初始空；输入框 maxLength=2000，提交 trim 后长度至少 5 | 梦境正文 |
| dreamDate | string，空或 yyyy-MM-dd | 做梦日期 |
| emotions | string，可空 | 梦境中的情感状态 |
| context | string，可空 | 最近经历、生活背景 |
| recurringDream | 空 / yes / no | 是否反复出现 |
| physiologySignals | string[]，初始 [] | 生理与睡眠线索，多选 |
| structureHint | string，可空 | 关键人物、场景、转折、结尾或惊醒方式 |
| locale | 当前页面 locale，本页 zh | 解读语言 |
| userId | 当前登录用户 id | 随页面请求传入；不能据此推断服务端信任客户端身份 |

## 完整调用链

```text
解梦页 W / 提交处理 eg
  ├─ 没有 user → showLoginModal() → 返回
  ├─ 正文 trim 后不足 5 字 → 显示校验提示 → 返回
  ├─ eh → 模块 86503.$0 / y
  │        └─ POST /api/validate-question { question, locale }
  │            ├─ 明确 data.isValid=false → reason / suggestion → 返回
  │            └─ 校验异常、失败或缺少数据 → 页面放行
  └─ 模块 30968.hL / T
       ├─ authClient.getValidAccessToken()
       ├─ d(input) → requestId
       └─ f('/api/dream', options, callbacks)
            ├─ 登录 token 存在时进行 divination_dream 积分预检
            ├─ POST JSON，接收 text/event-stream
            ├─ data → onChunk → 累加结果文本
            ├─ completed → onCompleted → 使用完整文本
            ├─ error / HTTP 错误 → 页面错误提示
            └─ 网络异常 → 有 questionId 尝试恢复；没有则有限重试
```

问题预校验的响应 JSON 在 `.data` 中包含 `isValid`、`reason`、`suggestion`。辅助函数外面还包一层 `{success,data,...}`，所以生产脚本里出现 `e.data.data`。

## 接口清单

| 方法及路径 | 作用 | 本次证据 |
| --- | --- | --- |
| GET /api/credits/cost?service=divination_dream | 查询按钮显示的费用 | 匿名页面实际请求 + 公开接口返回 |

| POST /api/validate-question | 正文有效性校验 | 客户端静态代码，未实调 |
| POST /api/dream | 发起流式解梦 | 客户端静态代码，未实调 |

完整传输协议见同目录 `接口与流式协议.md`。

## 页面状态与结果展示

- 任何表单修改都会清空结果、错误和校验提示，并隐藏结果区。
- 反复梦境按钮是 yes/no 选择；生理线索按钮通过 includes/filter 维护多选数组。
- 请求开始显示结果区及等待动画；结果区显示后约 200 ms 滚入视野。
- 第一段 onChunk 到达后关闭首包等待状态，累加文本并显示流式光标。
- onCompleted 用完整文本覆盖当前结果；onError 写入页面错误并移除流式状态。
- “重新输入”清空七个表单字段及相关页面状态。
- “查看历史”跳转到当前语言的 `/history?type=dream`。
- 通用结果组件为模块 86680，Markdown 子组件为模块 55864；文本按 Markdown 渲染，包含 remark 插件。
- 通用结果组件可识别“30秒结论 / 结论提要”“主体/详细/深度解读”“关键年份”等标题并分区。它是共享展示逻辑，不能据此认定服务端每次解梦一定返回这些标题。
- 共享展示组件具有复制、下载和记录相关逻辑；当前解梦调用只明确传入 completion、isLoading、onCompletion、error、onRestart，不应推断所有通用动作都能在这个页面正常完成。

页面首包到达后把加载状态置 false，而共享组件的自动滚动依赖 isLoading；这是实际观察到的状态绑定，复刻时需要独立考虑首包等待与流式接收是否共用一个状态。

## 匿名交互验证

REA 在独立临时浏览器中依次执行：打开目标页 → 等待 #dreamContent → 填入学校找教室的示例梦境 → 点击“分析梦境” → 等待 1200 ms → 采集截图、DOM 和可访问性文本。

结果：登录弹窗出现；本次采集的 API 请求是积分价格和积分规则请求，没有 `/api/dream`。这验证了匿名 UI 的登录拦截，不能单独证明服务端鉴权实现，也不构成登录后成功生成的验证。

证据完整性为 incomplete：部分网络请求在采集结束时尚未完成，部分网络内容不可用；没有丢弃事件。保留此限制，避免把短观察窗口解释为完整站点网络记录。
