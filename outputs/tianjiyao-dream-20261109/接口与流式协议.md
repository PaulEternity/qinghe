## 请求

`T`（偏移 10845）读取 `authClient.getValidAccessToken()`，如果有 token 以 Bearer 放在 Authorization。读取失败被忽略。随后调用共享 SSE 函数 `f('/api/dream', {method:'POST', headers, body:d(input), timeout:300000}, callbacks)`。

`d`（偏移 2008）保留原输入并补充 requestId。原 requestId 必须非空、长度不超过 100、符合 `/^qa_[a-z0-9_]+$/i`；否则生成 `qa_<Date.now()>_<Math.random().toString(36).slice(2,10)>`。

共享 `f`（偏移 2509）发送 JSON 请求，额外 header 为 `Content-Type: application/json`、`Accept: text/event-stream`，有效 requestId 还作为 `X-Reading-Request-Id` 发送。该请求使用原生 fetch，不走模块 86503 的 axios 401 自动刷新链。

有 Bearer 且没有 skipCreditCheck 时，客户端以 `dream → divination_dream` 检查积分。积分查询异常通常放行；明确积分不足回调 onError 后返回空字符串。实际服务端鉴权、扣费和幂等约束未知。

## SSE 协议

逐块 TextDecoder 解码，以换行拆分，读取 `event: ` 和 `data: `，data 多行拼接后 JSON.parse。空行或新 event 触发上一个事件处理。

| event | 观察到的 JSON 字段与行为 |
| --- | --- |
| connected | 任意事件存在 questionId 即保存；调用 onConnected() |
| meta | 仅当 type==='meta' 调用 onMeta(payload, questionId) |
| thinking | content 为真时调用 onThinking(content) |
| data | content 为真时累计到结果字符串并 onChunk(content) |
| completed | 字符串 content 替换累计结果；onCompleted(content, questionId, {finishReason: finishReason??null, truncated: !!truncated}) |
| error | onError(message || 'Unknown error') 并拒绝 Promise |

SSE 分支偏移：connected 5537；meta 5572；thinking 5643；data 5730；completed 5818；error 6008。JSON.parse 及事件处理异常被 catch 忽略。流正常结束即以当前累计内容触发完成，即使未观察到 completed event。

繁体 locale（zh-TW、zh-tw、zh-HK、zh-hk、zh-Hant）会进行客户端简繁转换；服务端文本是否本身已转换未知。

成功结束后对有 Bearer 的请求刷新积分，并可能派发会员升级提示事件。页面本身只使用 onCompleted 的第一个 content 参数。

## 断线与重试

- 共享函数 R（偏移 6543）：已获得 questionId 时，以 GET `/api/reading-recovery?questionId=<encoded>` 查询，透传原 Authorization。最多三次，后两次开始前等待 5000 ms。
- status=completed 且 content 非空：替换结果并完成。
- status=failed：向上层返回 failed。
- status=partial 且有 content：更新结果；继续后续查询。
- status=processing：立即返回 processing，不持续轮询。
- 其他失败/异常最终按 processing 处理。
- I（偏移 7283）捕获网络错误：若已经置完成标志 E，直接返回累计字符串；若已有 questionId，优先恢复且不重新提交生成请求。
- 没有 questionId 且错误匹配 network/connection/timeout/econnreset/enotfound/fetch failed/load failed，或 NetworkError，或 TypeError+fetch：最多重试两次，延迟 2000、3000 ms，沿用同一 body 和 requestId。
- `timeout=300000` 是单次 SSE Promise 超时设置；代码把 E 标志置 true 再 reject，外层见 E 会直接返回累计字符串。它没有使用 AbortController；不能推断其会终止服务器生成任务。
- 直接 SSE fetch 对 HTTP 401 没有观察到自动 refreshToken 重试。

## HTTP 错误

非 2xx 默认使用 HTTP 状态描述，若 JSON response 有 error 则采用其文案，error_type 则作为错误类型。INSUFFICIENT_CREDITS 会读取 required_credits/available_credits 并弹出积分提示，然后抛出带 skipToast=true 的错误；不会作为普通网络错误重试。

## 问题预校验

模块 86503 的 y（偏移 26516）调用 m('/api/validate-question', payload)，m（偏移 27200）发送 JSON POST；常规 auth fetch v（26751）自动附加有效 token，401 时尝试 refreshToken 并重发一次；非 OK 且 401 或 errorType=AUTHENTICATION_REQUIRED 时触发登录回调。y 返回 `{success:response.ok,data:json,error:json.error,errorType:json.errorType}`，网络异常返回 success=false、NETWORK_ERROR。

页面提交之前传 `{question: trimmedDreamContent, locale}`。页面仅在成功且 `responseJson.data` 存在时检查其 `isValid`、`reason`、`suggestion`；校验请求失败或数据缺失时放行。页面另有梦境正文至少五个字符的前置限制。该 UI 位于 `source-12-40498a271768d19ab829368700dd73ccd53b0ad9c82984cf705905728a67ada7.js`，校验调用偏移约 18348。

## 不应混淆的重试器

同 chunk 内另一个 `f`（模块 86503，偏移 26097）是 axios JSON 请求包装，不是 /api/dream 直接使用的 SSE f。它默认最多三次，延迟 1000/2000 ms，按错误关键词或 429/500/502/503/504/520–524 重试，同时排除部分鉴权/计费/参数错误关键词及 400/401/403/404。不要将此重试规则归到梦境 SSE 上。
