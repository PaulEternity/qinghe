# 清和 · 个人 AI 解读空间

一个本地运行的独立工程，参考东方命理工具的功能组织方式，采用自己的名称、界面、代码和 CSS 山月插画。没有会员、积分或支付；管理员账号负责管理 AI 访问码。适合个人使用，不能直接作为公网多用户服务部署。

## 管理员与 AI 访问码

首次启动自动创建账号 `admin`，随机管理员密码和初始六位数字 AI 访问码写入 `.local/admin-credentials.txt`（已被 Git 忽略，不通过 HTTP 提供）。使用顶部最右侧“登录 / 注册”登录 `admin` 账号，服务端验证管理员身份后才显示管理入口并进入管理页，可修改访问码和管理员密码。普通用户或未登录者直接访问 `#admin` 会转到账号页面。管理员与普通用户共用登录入口，切换角色会撤销原登录会话。修改后凭据文件中的旧值不再有效，请妥善保存或删除该文件。

所有 AI 解读、图片解读及追问由服务端验证访问权限。用户输入正确的六位数字访问码后，同一浏览器通过 HttpOnly Cookie 获得固定 5 分钟权限，刷新页面仍有效，调用 AI 不续期；到期后再次输入。管理员改码立即撤销所有 AI 验证，管理员改密撤销管理员会话，服务重启撤销所有会话。连续输错 5 次后暂停相应验证 5 分钟。本地排盘和查看札记不要求 AI 访问码。

管理员会话固定 30 分钟。管理员密码与六位码以独立随机盐的 scrypt 哈希保存在 `.local/access.json`；此文件需随本机配置保留并单独备份。管理员身份与普通用户账号分开，普通用户无法修改 AI 访问码。

## 用户账号与私人札记

顶部“登录 / 注册”提供用户名密码注册和登录。用户名为 3—32 位字母、数字或下划线（大小写归一，保留 `admin`），密码为 12—128 位。普通用户密码使用随机盐的 scrypt 哈希保存到 MySQL `users` 表；数据库只保存会话令牌的 SHA-256 摘要，浏览器使用 HttpOnly、SameSite=Strict Cookie。登录固定有效 24 小时，退出后服务端令牌失效，浏览器同步清除本次 AI 验证并刷新其他标签页。

生成盘面、查看札记及 AI 请求均需先登录。列表、导入、翻牌、删除、清空、AI 解读和追问的数据库操作均限定当前登录用户；客户端提交的用户 ID 不参与授权。AI 访问码仍为固定 5 分钟有效，并绑定具体登录会话，切换账号或重新登录后需重新验证。

首次迁移为 `readings` 增加可空的 `owner_id`，旧记录保持未归属，不会自动分配给首个注册用户。管理员页面“迁移旧札记”可将全部未归属记录分配给一个已经注册的用户名，不改变已有用户的记录。本机迁移前备份位于 `.local/readings-before-users.json`，不会上传 Git。旧浏览器札记只能由用户手动导入到自己的账号；同 ID 的其他用户记录不能被占用或覆盖。

已有数据库首次升级需由数据库管理员执行建表与归属字段迁移（`MysqlStore.init()` 与 `UserAccounts.init()`），涉及 CREATE、ALTER、INDEX、REFERENCES；本机已完成一次性迁移，日常应用账号未新增上述权限。新安装请先用迁移账号完成初始化，再使用应用账号启动。新建 `users` 与 `user_sessions` 表，用户登录数据可以随数据库备份；服务重启不注销普通用户的 24 小时会话，但会清除内存中的 AI 验证与管理员会话。

尚未提供邮箱验证、找回密码、用户改密和账号删除。仍只允许本机访问，公网托管适配需另行完成。用户隔离测试使用独立的 `_test` 数据库，运行：`MYSQL_INTEGRATION=1 node --env-file=.env --test accounts.integration.test.mjs`（Windows 使用 PowerShell 设置环境变量）。

## 接入自己的模型

1. 在工程目录将 `.env.example` 复制为 `.env`。
2. 填写 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_NAME`。
3. 停止并重新执行 `npm start`。

`MODEL_BASE_URL` 填服务商兼容接口的 API 根地址，例如服务商文档中包含 `/v1` 的根路径，不要重复加 `/chat/completions`。本工程会在根路径后追加 `/chat/completions`，使用 Bearer Key；界面解读使用 SSE 流式请求（服务商须支持 stream=true），旧 JSON 接口仍可用。提供商必须支持该协议；手相需要视觉模型。没有为任何服务商预设凭据。

密钥由服务端从 `.env` 读取，不放进浏览器，不通过页面编辑。`.env` 已被 Git 忽略，交付压缩包也排除该文件。无需把真实 Key 发到聊天中。模型服务可能收费；“免费”指此工程没有会员与使用次数限制。

未配置模型时，八字、紫微、抽牌和起卦可以生成本地事实；点击 AI 解读时明确显示未配置，不提供假回复。梦境、起名等依赖模型的内容须配置后使用。

## 功能与边界

| 功能 | 当前实现 |
| --- | --- |
| 八字 | lunar-javascript 生成四柱、五行、纳音；AI 根据事实解读 |
| 紫微 | iztro 2.6.3；十二宫、命身宫、主辅曜/杂曜、四化、大限与所选日期的流年依据；单盘配置隔离 |
| 塔罗 | 韦特 78 张，单牌/三牌/凯尔特十字十牌，三牌四种视角；无放回抽牌，逐张或全部翻牌 |
| 六爻 | 自动三钱法或手动 6/7/8/9；京房八宫本变卦、纳甲、六亲六神、世应、旬空、伏神；不自动确定用神与应期 |
| 双人合盘 | 两份四柱作为模型输入；没有自研量化契合度算法 |
| Offer 对比 | 用户四柱与手填的 A/B 方案交给模型比较；未做招聘截图 OCR |
| 起名、梦境 | 结构化输入与模型解读；起名含四柱，不是确定性的喜用神评分引擎 |
| 手相 | 单张 JPEG/PNG/WebP 图片交给用户配置的视觉模型；未复刻原站四图流程 |
| 追问 | 原排盘/原牌面 + 本次解读与历史消息；为控制上下文，最多约 7 轮追问 |
| 札记 | 本机 MySQL 持久化，查看、复制、文本导出、删除、清空及旧浏览器札记导入 |

出生输入为公历 UTC+8 标准时间，范围 1900—2100，不支持农历输入和海外时区。可选真太阳时校正：输入经度，按 NOAA 分数年近似式计算均时差，再加经度偏移；结果取整到分钟，保存原始时间、算法版本、两个偏移分量、校正后时间及跨日/跨时辰标志。开启后紫微和四柱使用校正后的时间；合盘双方独立校正。六爻记录起卦时间与校正口径，但完整纳甲排盘仍待后续实现。

校正不能等同于更准确的命理预测。原始时间必须已还原到 UTC+8 标准时，历史夏令时不自动识别；边界时间请对照两种口径。本式为近似计算，不作为秒级天文计算。公式来源：https://gml.noaa.gov/grad/solcalc/solareqns.PDF 。八字采用 lunar-javascript `sect=2`；紫微沿用 iztro 的时辰与闰月规则，不保证不同命理流派的结果完全一致。

尚未实现：跨服务器多端同步、日/月/年运势专区、独立自由聊天、完整知识库，以及原站全部交互细节。这是可运行的首版工程，尚非原站全量等价实现。

## 数据和安全

- 只监听 `127.0.0.1`，限制 Host 和跨站请求，静态文件使用白名单，`.env` 无公开路由。
- 出生信息、问题、照片会发送给你配置的模型服务，请按其隐私政策使用。
- 札记含出生信息、提问和回复，保存在本机 MySQL，不包含原始照片或模型 API Key，未做应用层加密。数据库持久化不等于备份，请定期导出。
- 已实现用户登录和札记归属校验；尚无完整的并发成本控制、审计或公网滥用防护，不应改绑 `0.0.0.0` 直接上线。
- 传统文化与 AI 输出不能保证事实准确性；排盘计算与人生预测是两回事。

## 本机数据库运行

- 当前配置：MySQL 8.4，`127.0.0.1:3307`，数据库 `qinghe`，应用账号 `qinghe`。
- 首次本机凭据已写入 `.env`，管理账号配置在 `.local/mysql-admin.cnf`；均被 Git 忽略，勿提交、发送或打包。其他机器需自行创建数据库和专用账号，再填写 `.env.example` 中的连接项。
- `npm run db:start` 在当前终端常驻运行本机数据库（另开终端启动应用），`npm run db:status` 确认运行，`npm start` 启动清和。`npm run db:stop` 正常停止数据库。管理脚本适用于当前 macOS Homebrew 安装；没有设置开机启动。
- MySQL `readings` 表保存 JSON 札记；使用 InnoDB 原子更新和 revision 乐观锁，防止过期请求覆盖新数据。数据库停用时应用不能保存札记，会明确报错。
- 旧浏览器数据：打开“我的札记”点击“导入旧浏览器札记”，同 ID 只插入一次，不覆盖数据库较新的内容；浏览器原数据仍保留。
- `npm test` 跑普通回归；`npm run test:mysql` 显式连接本机真实数据库，使用模拟模型验证持久化。测试只删除自身创建的记录。
